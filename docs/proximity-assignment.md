# 景点日期分配的邻近关系评分

日期分配使用已有交通矩阵，不额外增加地图 API 查询。OR-Tools 保留偏好、类别多样性、交通与费用评分，并增加同天邻近奖励。

- 对每对候选景点，取双向交通时间的较大值，避免单向便捷导致误判。
- 邻近分数为 `max(0, 30 - 双向最大交通分钟数)`。
- 使用布尔变量表示两个景点是否同时安排在某一天，加入精确 AND 约束。
- 同天邻近奖励为分数之和乘以 `ObjectiveWeights.proximity`，默认权重为 4；设为 0 可关闭奖励。
- 每日容量、可用日期、预算等约束仍优先成立；邻近奖励不强制景点同天安排。

这是日期分组的软评分，不代表实际路线总时间，也不保证最短路径。当天游览顺序仍由交通矩阵的最近邻排序确定，具体时间和返程由后续排程与硬校验检查。

降级方案保留原有每日数量配额：先选排序最高的剩余景点作为当天种子，再优先选择与当天已有景点最近的地点。降级分组使用坐标直线距离，具体路线仍由后续交通数据计算与校验。

## 观察与验证

日志 `optimization.proximity_pairs` 显示邻近候选对数量；`optimization.proximity_assignment` 显示各风格的分组及分数。优化结果的 `objective_breakdown.proximity_score` 提供未乘权重的同天邻近分数。降级分组可通过 `planning.fallback_proximity_assignment` 观察。

`tests/test_proximity_assignment.py` 验证邻近分组、每日容量与开放日期优先、双向交通差异，以及降级时避免轮流分配拆散邻近地点。
