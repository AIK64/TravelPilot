# 景点候选发现与默认数据

## 检索与工具轨迹

固定工作流与动态 Planner 的 `poi.search` 均先查询必去地点，再用目标城市、关键词“景点”和风景名胜分类 `110000` 发现候选。兴趣偏好参与后续评分，不直接作为商户搜索关键词。抵离和住宿锚点继续按名称查询。

高德 v5 搜索使用 `region` 和 `city_limit=true` 限定城市。高德模式下，`QunarScenicPOIProvider` 同时读取去哪儿公开门票列表第一页，优先保留经高德确认的去哪儿景点，并合并高德候选。新候选最多核实5个，核实阶段最多2秒；查询结果继续进入既有 Gateway 缓存、Graph 状态、路线矩阵和验证流程。餐厅不纳入本次发现范围。

去哪儿不需要额外 Key，使用 `https://piao.qunar.com/ticket/list.json`。这是网站公开请求接口，其可用性和字段可能变化；请求失败、响应无效或地点核实超时时保留高德结果。高德本身失败仍保持原有工具错误及重试语义，不伪装为业务不可行。

`qunar.scenic.merged` 日志包含高德候选数、去哪儿候选数、确认数和最终数量；`qunar.scenic.unavailable`、`resolve_failed`、`resolve_timeout` 记录降级原因。原始响应和 Key 不进入 Graph 或日志。来源合并后沿用高德 POI ID 和坐标，路线工具保持一致。

## 关键词去重

候选进入跨天分配前，先按ID或名称关系分组，每组保留输入排序最优的记录。名称比较移除空白、括号备注和末尾“风景名胜区／景区／公园／博物馆”等通用后缀；归一化关键词至少2字且互相包含时判重。例如“大开元寺”和“大开元寺普贤楼”不会分别占用活动时长和费用。硬校验也检查同一方案跨天出现的名称包含重复。

日志 `planning.poi_duplicate_excluded` 记录剔除与保留的POI ID及判重原因。此规则不代表已确认父子关系，可能误合并名称包含的独立地点，也不能识别名称差异较大的别名（如“泉州大开元寺”和“泉州开元寺-仁寿塔”）。代表的原始名称、坐标和费用保留，不合并不同记录的事实。

## 价格和时长

- 匹配到去哪儿有效挂牌价时，用它补充或覆盖参考费用；挂牌价不代表指定日期、票种的最终购票价。
- 去哪儿缺失价格保持未知，不当作免费；API 明确返回的0元保留。
- `assume_with_warning` 下，缺失人均费用按45元估算，总活动费用乘以出行人数；缺失游玩时长按120分钟（2小时）估算。
- 默认值保留 `PlanningAssumption`、`ValueSource.DEFAULT` 和数据置信度扣减，验证结果仍提示费用及游玩时长未经 Provider 确认。原始 `POIFacts` 不被改写为默认事实。
- `strict` 仍拒绝关键事实缺失的候选。
- 缺失营业时间默认按08:00–18:00开放，保留默认假设标记；API返回的有效营业时间仍优先使用。跨天分配、真实路线查询及硬约束验证保持既有实现。

## 验证

`tests/test_qunar_provider.py` 覆盖候选核实、价格合并、免费/缺失价格和补充源降级；`tests/test_search_plan.py` 验证分类检索及必去地点优先；`tests/test_defaults.py` 验证默认值、来源和人数计算；`tests/test_amap_provider.py` 验证高德请求参数。
